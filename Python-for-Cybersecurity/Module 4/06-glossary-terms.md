# Module 4: Terms and Definitions

## Errors and debugging

| Term | Definition |
|------|-----------|
| **Debugging** | The practice of identifying and fixing errors in code |
| **Debugger** | A software tool that helps to locate the source of an error and assess its causes |
| **Syntax error** | An error that involves invalid usage of a programming language |
| **Logic error** | An error that results when the logic used in code produces unintended results |
| **Exception** | An error that involves code that cannot be executed even though it is syntactically correct |
| **IDE** (Integrated development environment) | A software application for writing code that provides editing assistance and error correction tools |

---

## Code building blocks

| Term | Definition |
|------|-----------|
| **Variable** | A container that stores data |
| **Function** | A section of code that can be reused in a program |
| **Conditional statement** | A statement that evaluates code to determine if it meets a specified set of conditions |
| **Iterative statement** | Code that repeatedly executes a set of instructions |

---

## Working with files and data

| Term | Definition |
|------|-----------|
| **File path** | The location of a file or directory |
| **Log** | A record of events that occur within an organization's systems |
| **Parsing** | The process of converting data into a more readable format |

---

## The big picture

| Term | Definition |
|------|-----------|
| **Automation** | The use of technology to reduce human and manual effort to perform common and repetitive tasks |

---

## Quick recall

- **Three error types:** syntax (invalid language use), logic (wrong result, no error message), exception (valid syntax, can't run)
- **Debugging tools:** debuggers and IDEs
- **Code structure:** variables store data, functions reuse code, conditionals make decisions, iterative statements repeat

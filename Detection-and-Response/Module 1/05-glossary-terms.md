# Module 1: Key Terms and Definitions

## 1. Incident Response
- **CSIRT (Computer Security Incident Response Team):** A specialized team of security professionals trained in incident management and response.
- **Incident:** An event that threatens the confidentiality, integrity, or availability (CIA) of information or systems, or violates security policies or laws.
- **Incident Response Plan:** A document describing the procedures to follow during each step of incident response.
- **Incident Handler's Journal:** Documentation used to record information and actions during incident response.
- **Documentation:** Recorded content used for a specific purpose.
- **Playbook:** A manual that provides detailed instructions for operational actions.

## 2. Security Teams
- **SOC (Security Operations Center):** An organizational unit responsible for monitoring networks, systems, and devices for security threats or attacks.
- **CSIRT:** A specialized team responsible for managing and responding to security incidents.

## 3. Security Detection Tools
- **IDS (Intrusion Detection System):** Monitors system activity and alerts security professionals about possible intrusions.
- **IPS (Intrusion Prevention System):** Monitors system activity and takes action to stop intrusions.
- **EDR (Endpoint Detection and Response):** Monitors endpoints to detect, analyze, and respond to malicious activity.
- **SIEM (Security Information and Event Management):** Collects and analyzes log data to monitor important activities in an organization.
- **SOAR (Security Orchestration, Automation, and Response):** A collection of applications, tools, and workflows that uses automation to respond to security events.

## 4. Events and Detection Results
- **Event:** An observable occurrence on a network, system, or device.
- **True Positive:** An alert that correctly identifies an actual attack.
- **True Negative:** No malicious activity exists, and no alert is generated.
- **False Positive:** An alert incorrectly identifies harmless activity as a threat.
- **False Negative:** An actual threat exists, but the system fails to detect it.

## 5. NIST Incident Response Lifecycle
A framework consisting of four phases:

1. **Preparation:** Establish tools, policies, procedures, and trained teams.
2. **Detection and Analysis:** Identify suspicious activity and investigate potential incidents.
3. **Containment, Eradication, and Recovery:** Limit the damage, remove the threat, and restore normal operations.
4. **Post-incident Activity:** Review the incident, document lessons learned, and improve future responses.

## 6. Quick Revision
- **IDS:** Detects and alerts.
- **IPS:** Detects and blocks.
- **EDR:** Detects and responds to endpoint threats.
- **SIEM:** Collects and analyzes logs.
- **SOAR:** Automates security workflows and responses.
- **SOC:** Monitors and protects an organization's systems.
- **CSIRT:** Manages and responds to security incidents.
- **Playbook:** Step-by-step operational instructions.
- **Incident Response Plan:** Procedures for handling security incidents.
- **NIST Lifecycle:** Preparation → Detection and Analysis → Containment, Eradication, and Recovery → Post-incident Activity.
